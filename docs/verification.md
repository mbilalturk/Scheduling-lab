# Verification

## Reproduce the checks

```sh
npm ci
npm test
npm run build
npm run preview
```

The test command compiles the TypeScript core and tests into `.test-build/`, then uses Node's built-in test runner. The build command includes strict type checking before creating the static site in `dist/`.

## Automated coverage

The suite currently contains **95 tests**:

- Twelve hand-calculated A/B cases cover FCFS, SJF, SRTF and Round Robin with quantum 1, 2 and 4. Assertions compare exact timelines, per-process metrics and averages.
- Additional workloads cover initial/middle idle time, simultaneous arrivals and scheduling ties, and SRTF preemption with equality handling.
- General properties are checked over 320 deterministic algorithm/workload combinations: specified CPU time is conserved, no process runs before arrival, intervals do not overlap, waiting/response are nonnegative, and CPU is not idle while work is ready.
- Input validation, repeatability, caller-input immutability, typed options, form transitions and chart presentation have dedicated tests.
- Single-flow UI tests verify that the process inputs, policy radios and submit action are in one form, quantum is conditional on RR, and old result context is preserved across edits and failed reruns.
- Compile-time checks in `type-tests/contracts.ts` reject missing RR quantum, unsupported policies and mutation of readonly public data.

The original 63 tests and hand-calculated fixtures were retained unchanged during the JavaScript-to-TypeScript migration. Additional differential checks against the previous implementation covered 4,000 algorithm/workload combinations with matching full results. Expected fixtures are not generated by the implementation under test.

## Browser verification

The earlier production bundle was checked with all twelve A/B scenarios. Displayed averages and interval counts matched the hand calculations. Editing, add/remove, duplicate IDs, blank numeric values, chart zoom, exact-trace pagination and keyboard interval selection were exercised. The single-flow update replaces stale-result removal with explicit previous-run retention. Narrow layouts use local scrolling for the chart and tables.

The single-flow update was also checked in a local production preview with all twelve A/B scenarios. Repeated edits and failed reruns kept the previous result's original labels and selected timeline interval; a successful update replaced the snapshot. Native radio keyboard navigation, conditional quantum, one-column mobile layout and absence of page-level horizontal overflow were checked. The primary, body, secondary and warning text color pairs exceed 4.5:1 contrast. These checks are local verification, not a claim that this update has already been deployed.

These are documented browser checks, not an installed end-to-end test suite. No claim is made of a complete cross-browser matrix, screen-reader certification or performance benchmarking at the maximum 10,000 RR slices.

## Regression examples

### Keyboard navigation across long timelines

The initial React chart made every interval a separate Tab stop. A valid long Round Robin schedule therefore made subsequent controls difficult to reach by keyboard. A regression test rendered 1,000 intervals and failed because it found 1,000 interval Tab stops instead of one.

The chart now uses roving focus: only the selected interval participates in the Tab sequence. Left/Right arrows, Home and End move between intervals. Both the rendered-output regression and the browser keyboard check passed after the fix. Scheduling results were unaffected.

### SVG tooltip text

A React render test found that an SVG title composed of multiple JSX children produced an empty title in server rendering. Passing a single template string preserves the exact interval description. The regression verifies the actual rendered tooltip text.
